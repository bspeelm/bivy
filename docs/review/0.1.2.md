# 0.1.2

A release-machinery release, like 0.1.1. Nothing in the program changed.

## What changed since 0.1.1

**A release build records nothing about the git it was built from.**

Verifying 0.1.1 turned up a false alarm of exactly the kind reproducibility is
supposed to prevent. Rebuilding the tag in a linked git worktree produced
different checksums from the published archives, with byte-identical source
and the same compiler. Go stamps the main module version from the VCS, and git
describes checkouts holding the same bytes differently: a clone at the tag
reports `v0.1.1`, a worktree reports `(devel)`, a tree with one file touched
reports itself modified.

Anyone who took the rebuild-and-compare offer seriously enough to try it in a
worktree would have concluded the archive had been tampered with. `make dist`
now builds with `-buildvcs=false`, so byte-identity depends on the source and
the compiler and nothing else. `bivy version` still prints the version, which
is stamped explicitly rather than inferred from git.

## What was checked

| check | result |
|---|---|
| `make check` on Linux and macOS, in CI | green |
| the scheduled integration workflow, both platforms | green |
| `make dist-reproducible` | two builds, byte-identical |
| the same commit built in a clone, in a worktree, and in a modified tree | all three identical |
| rebuilding the published archives from a plain clone | identical |

The third and fourth rows are this release. The same commit was built from the
working repository, from a linked worktree, and from a tree with an untracked
edit to a file the archive does not carry; all three produced identical
archives. Before this change the worktree differed from the other two.

Playback was verified by hand again, because CI cannot do it (ADR-015): a real
video, resolved by mpv's own extractor hook, played to its end and reported
`end-file eof`.

## What was not checked

Unchanged from 0.1.1.

- **Stream resolution and playback are not covered by CI, and cannot be.**
  Hosted runners are bot-challenged and the remedy on offer is a cookie, which
  ADR-004 refuses. The most-used path in the program is verified by hand and
  by nothing else.
- **Nobody has launched bivy on macOS.** The suite and the integration tests
  both run there; no person has started the program on a Mac. PLAN.md §12 asks
  for that pass and it is still outstanding.
- **Thumbnails have no automated test that draws pixels.** Confirmed by eye on
  Linux, in a terminal speaking the kitty protocol inside a multiplexer.
- **Whether a terminal answers the cell-size query through a multiplexer is
  unknown.** Where it does not, the picture is softer than it needs to be and
  nothing fails.
- **No security review by anyone outside this project.**
- **Nothing has been tested at scale** — a handful of followed channels.
- **The archives are not signed** (ADR-014). What stands in for that is the
  rebuild, which is why two releases running have been spent on making it
  actually work.

## Known outstanding

Unchanged: playback from inside a container needs the host's mpv, and PLAN.md
§13 still lists the open decisions.
