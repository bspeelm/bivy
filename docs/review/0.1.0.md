# 0.1.0

The first release. Following channels, a dashboard of what is new, search,
opening a channel, playback in mpv, and thumbnails where the terminal can draw
them.

## What it does

- **Follow channels** by handle, channel URL, or identifier, and see what they
  have posted since the last visit.
- **Search** for videos or for channels, and follow one from the results.
- **Open a channel** and page through its videos.
- **Play** in mpv's own window, driven over an IPC socket. bivy never puts a
  stream URL in an argv and never decodes anything itself.
- **Thumbnails** for the row under the cursor, through the kitty graphics
  protocol, on terminals that answer the capability probe. Text-only elsewhere.
- **A vim-style command line** for everything that takes an argument, keys for
  everything that does not.

It holds no account, reads no cookies, downloads nothing, and writes two
directories: one for configuration, one for data.

## What was not checked

This is the half worth reading.

- **Nobody has launched bivy on macOS.** The test suite runs there on every
  commit and the binary cross-compiles, but no person has started the program
  on a Mac, watched it draw, or played a video with it. `internal/store`
  chooses its directories by platform, so that branch is covered by tests and
  by nothing else. PLAN.md §12 asks for this manual pass and it is outstanding.
- **Thumbnails have never been verified by an automated test drawing pixels**,
  because no test can assert what a terminal put on a screen. They were
  confirmed by eye during development, on Linux, in a terminal speaking the
  kitty protocol inside a multiplexer. On macOS the graphics path is unrun by
  any human.
- **Whether a terminal answers the cell-size query through a multiplexer is
  unknown.** When it does not, bivy assumes a cell size and the picture is
  softer than it needs to be; it is not wrong, and nothing fails.
- **No security review by anyone outside this project.** The privacy claims
  rest on the one-package network rule, which `make budgets` asserts
  mechanically on every commit. That is a real check, and it is not the same
  thing as somebody having looked.
- **Nothing has been tested at scale.** The feed path has been exercised
  against a handful of followed channels, not hundreds.
- **The archives are not signed** (ADR-014). The checksums detect a damaged
  download, not a substituted one.

## Known outstanding

- Playback from inside a container needs the host's mpv; a container's own mpv
  cannot reach the host compositor and fails on dmabuf import. The README says
  so under Requirements. bivy does nothing about this automatically, and
  whether it should is undecided.
- PLAN.md §13 still lists open decisions, including what bivy should do when
  the extractor is absent entirely.
