# 0.2.4

One change in the program: where a screenshot goes. It is a bug fix, and it is
also an amendment — the write set §8 declares was already wrong, and had been
for every version that could play a video.

## What changed since 0.2.3

mpv binds a key to a screenshot and writes it to `screenshot-dir`, whose
default is empty, which means the working directory it inherited. bivy launches
mpv from wherever bivy was started, so pressing that key put a frame of a video
in whatever directory that happened to be.

bivy now passes `--screenshot-directory`: `XDG_PICTURES_DIR` where that names
an absolute path, else `Pictures` under the home directory, and the flag left
off entirely where no home can be found, so mpv keeps its own default rather
than being handed an empty string. Only an absolute path is taken, because the
value reaches an argv (§7).

**The honest framing is not "bivy chose a bad place" but "bivy chose no
place."** That is why this release also edits PLAN §8 and the north-star, which
both claimed nothing is written outside the two directories. They now say what
is true, and ADR-023 carries the reasoning with the argument against it stated:
this is a third location, in a home directory bivy neither owns nor creates.

## What was checked

| check | result |
|---|---|
| the flag against the installed player, over its IPC socket | the file lands where it is told |
| the directory does not exist yet | mpv creates it |
| anything still reaching the working directory | no, in either case |
| the whole flag set with it added, against a real player | accepted, mpv 0.41.0 |
| `make check` | exit status 0, `conformant.`, 15 ok / 0 failed |
| CI on Linux and macOS | green on both |

The first four are the ones this release rests on, and they were measured
rather than read off mpv's documentation — a flag the player rejects is a
player that never starts, which no unit test of our own argv would notice.

**The isolation test is untouched and still asserts the write set exactly.** A
screenshot happens on a keypress and never otherwise, so a first launch still
writes exactly two directories. Nothing was weakened to accommodate the third.

## What was not checked

- **Nothing in the pacing and pushback work has met the live service.** The
  gate has never been seen to trip on a real refusal, and the strings
  `pushback.Detect` looks for were reasoned from the shape of an error rather
  than captured from one. If the service words a refusal differently the gate
  will not fire and bivy behaves as it did before 0.2.2. This is still the
  weakest link in the program, and it is now three releases old.
- **The screenshot was never taken through bivy's own interface.** The player
  was driven directly over its socket with a generated clip. What is proven is
  that the flag works and that the argv bivy builds is accepted; what is not is
  a person pressing the key during a video bivy resolved.
- **Nobody has launched bivy on macOS.** The suite runs there and `Pictures`
  under home is the convention there too, but that path has never been written
  to by this program on that platform (PLAN.md §12).
- **Nothing has been tested at scale** — a handful of followed channels.
- **No security review by anyone outside this project.**

## Known outstanding

- **There is now a third place bivy writes**, and it is the only one bivy does
  not own or create. ADR-023 is the record, including what would reopen it.
- **Building from source needs a Go that will fetch the toolchain `go.mod`
  names.** A distro-packaged Go that defaults `GOTOOLCHAIN=local` refuses the
  build outright rather than warning. `scripts/dist.sh` pins the toolchain for
  a release build; the Makefile's own build target does not, so it inherits
  whatever the machine decided. Setting `GOTOOLCHAIN=auto` in the environment
  is the whole fix, and nothing in the repository says so yet.
- **The comment budget has no headroom.** Comments sit at 25% of code against a
  ceiling PLAN.md §0 calls hard. This release moved code and comments together
  and landed on the ceiling exactly; the next comment meets it.
- **The gate cannot be reopened without restarting bivy** (ADR-017), which is
  deliberate and still the sharpest edge in the program.
- **The User-Agent decision is open.** ADR-020 is proposed, not accepted, and
  nothing in the code has changed.
- Search still holds the loop for as long as the extractor takes.
- PLAN.md §13 still lists the open decisions.
