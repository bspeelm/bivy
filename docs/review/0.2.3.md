# 0.2.3

Nothing in the program changed. Three pins moved, and one of them decides
what a published archive rebuilds into, so it was checked rather than taken.

## What changed since 0.2.2

| pin | from | to | |
|---|---|---|---|
| `golang.org/x/term` | v0.46.0 | v0.47.0 | the only direct dependency there is |
| `golang.org/x/sys` | v0.48.0 | v0.49.0 | indirect |
| the toolchain line in `go.mod` | go1.26.8 | go1.26.9 | newest patch in the line already named |

The weekly check found all three and acted on none of them, which is what it
is for. Each was confirmed against upstream before being taken rather than
read off the issue it opened.

**The toolchain line is the one that mattered.** `scripts/dist.sh` pins
`GOTOOLCHAIN` from it, so it decides what a tag rebuilds into — and ADR-014
ships no signatures, which makes a byte-identical rebuild the whole guarantee
rather than a nice property. It was moved only after two builds of the commit
were confirmed identical on the new compiler.

**The line itself did not move.** go1.26 is still one of the two lines Go
supports. It is now the older of them, and moving a line rather than a patch
raises the minimum for anyone building from source, which is why the check was
narrowed to patches in 0.1.5 and why the next report about this line is a
different question from this one.

## What was checked

| check | result |
|---|---|
| the three pins, against upstream | all three confirmed; the issue was accurate |
| `go mod verify` | all modules verified |
| `make check` | exit status 0, `conformant.`, 15 ok / 0 failed |
| `make dist-reproducible` on the new compiler | two builds, byte-identical |
| CI on Linux and macOS | green on both |

The last two are the ones this release rests on. The reproducible build says
the compiler change did not cost the property the release process depends on,
and CI says the pinned patch is actually fetchable on both platforms — which
the maintainer's machine could not answer, because a distro-packaged Go
refuses to fetch a toolchain at all.

The binary grew by about eight kibibytes on the new compiler, against a budget
with a third of its room spare.

## What was not checked

Unchanged from 0.2.2, and worth repeating rather than pointing at:

- **Nothing in the pacing and pushback work has met the live service.** The
  gate has never been seen to trip on a real refusal, and the strings
  `pushback.Detect` looks for were reasoned from the shape of an error rather
  than captured from one. If the service words a refusal differently the gate
  will not fire and bivy behaves as it did before 0.2.2. This is still the
  weakest link in the program.
- **No playback by hand this release.** Nothing in the player changed, and
  ADR-015 already says stream resolution cannot be covered by CI.
- **Nobody has launched bivy on macOS**, on this compiler or any other. The
  suite runs there; no person has started the program (PLAN.md §12).
- **Nothing has been tested at scale** — a handful of followed channels.
- **No security review by anyone outside this project.** Both module bumps
  were taken because they were current, not because anybody read the diff.

## Known outstanding

- **An archive rebuilds only on the compiler it was built with.** 0.2.2 and
  everything before it were built on go1.26.8; this release and anything after
  it on go1.26.9. Reproducing an older tag means using the line that tag
  names, which is what pinning from `go.mod` makes possible and what a floor
  would have made impossible.
- **The comment budget has almost no headroom.** Comments sit at 25% of code
  against a ceiling PLAN.md §0 calls hard, with a handful of lines to spare.
  Nothing in this release moved it, and the next change to add a comment will
  meet it.
- **The gate cannot be reopened without restarting bivy** (ADR-017), which is
  deliberate and still the sharpest edge in the program.
- **The User-Agent decision is open.** ADR-020 is proposed, not accepted, and
  nothing in the code has changed.
- Search still holds the loop for as long as the extractor takes.
- PLAN.md §13 still lists the open decisions.
