# 0.2.5

Playback that keeps up at high bitrates, an optional proxy, a screen that says
what it is waiting for, and one bug that could end a session over a single
video. Three pins moved as well, one of which decides what this tag rebuilds
into.

## What changed since 0.2.4

**An age-restricted video no longer stops the session.** The bot check was
matched on words the service also uses to say a video needs an account for its
age, so one such video shut the gate (ADR-017) and stopped feeds, search and
thumbnails until restart. Only the bot check shuts it now; the age notice
reaches the status line as what that one video said.

**Video is asked for in short requests.** mpv's ffmpeg opens one open-ended
request per stream and the video host slows those down, so a 4K stream could
stall on a fast connection. mpv now asks 5 MB at a time. Quality is unchanged.

**Video is decoded on NVIDIA's decoder where there is one**, and on the
processor everywhere else, as before. The decoder is named rather than left to
mpv's `auto`, which picks the Vulkan decoder, and that one froze mpv on AV1.

**A proxy is offered** (ADR-024): `bivy --proxy http://host:port` sends feeds,
thumbnails, search and video through that address. It is off by default and
never falls back to connecting directly. An address holding a password is
refused, because it would reach an argv (§7).

**The screen says what is loading.** The dashboard is drawn at once with
`fetching…` rather than staying blank until every feed answers, a search in
progress no longer reads as "nothing found", and `bivy list-only` names the
channels that failed instead of saying none answered when some did.

**Three pins moved**, found by the weekly check and confirmed against upstream
before being taken:

| pin | from | to | |
|---|---|---|---|
| `golang.org/x/term` | v0.47.0 | v0.48.0 | the only direct dependency there is |
| `golang.org/x/sys` | v0.49.0 | v0.50.0 | indirect |
| the toolchain line in `go.mod` | go1.26.9 | go1.26.11 | newest patch in the line already named |

## What was checked

| check | result |
|---|---|
| `go mod verify` | all modules verified |
| `make check` on go1.26.11 | exit status 0, `conformant.`, 15 ok / 0 failed |
| `make dist-reproducible` on go1.26.11 | two builds, byte-identical, all four platforms |
| CI on Linux and macOS, with the pins moved | green on both |
| short requests, same 4K video and route, from mpv's own cache state | about 18 Mbit/s before, about 67 Mbit/s after |
| NVIDIA decoding, 4K60 AV1 in a real window, four minutes, 14 seeks | mpv always answered, no dropped frames |
| a decoder that does not exist, on a local file | played on the processor |
| bivy, mpv and the extractor keeping to the proxy | connections sampled during list-only and 4K playback; one leak found and fixed |
| launch and search messages | tried by hand in a real session |

The proxy row is the one that earned its place. Unit tests can show which flags
bivy passes and cannot show that the programs it launches honour them; the
sampling found that mpv's extractor hook ignores `--http-proxy`, so the lookup
left directly while the video went through the proxy. A deliberate direct
connection was caught first, to prove the sampling could see one.

Each behaviour change names its test: `TestAnAgeRestrictedVideoDoesNotStopTheSession`,
`TestDetectReadsWhatTheServiceSaid`,
`TestVideoIsAskedForInShortRequestsSoHighBitratesCanKeepUp`,
`TestVideoIsDecodedByNvidiasDecoderAndNotLeftToAuto`,
`TestTheScreenIsDrawnBeforeTheFeedsHaveAnswered`,
`TestASearchStillRunningDoesNotSayItFoundNothing` and
`TestListOnlyDoesNotSayNoFeedsAnsweredWhenSomeDid`.

## What was not checked

- **No real age-restricted video was played.** The fix rests on the wording of
  the notice and on tests that fail against the old detector.
- **The bot check has still never been seen to trip on a real refusal.** The
  strings `pushback.Detect` looks for are narrower than they were, which makes
  a differently worded refusal more likely to pass unnoticed, not less.
- **Short requests were measured through a proxy only**, never on a direct
  connection, and against one ffmpeg. An ffmpeg without the option should
  ignore it; none was tried.
- **Hardware decoding was tried on one machine with an NVIDIA card.** A machine
  without one, and a Mac, were only simulated by naming a decoder that does
  not exist. The Vulkan freeze was seen once and its trigger is unknown, so
  four clean minutes is a good sign and not proof.
- **The proxy was tested on Linux, with one proxy and one mpv.** Sampling can
  miss a very brief connection and does not reliably show name lookups. A
  connection dropped mid-video was not tried.
- **The upstream notes for go1.26.10, go1.26.11 and the two modules were not
  read.** They were taken because they were current.
- **Nothing was played by hand on go1.26.11.** The hand checks above were made
  on builds from before the pins moved.
- **Nobody has launched bivy on macOS** (PLAN.md §12).
- **Nothing has been tested at scale** — a handful of followed channels.
- **No security review by anyone outside this project.**

## Known outstanding

- **Loading can take ten to thirty seconds and nobody has timed why.** The
  screen now says it is fetching; it is no faster, and keys other than Ctrl-C
  wait for the feeds.
- **An archive rebuilds only on the compiler it was built with.** 0.2.3 and
  0.2.4 were built on go1.26.9; this release on go1.26.11.
- **go1.26 is the older of the two lines Go supports.** The next line to
  appear ends its security fixes, and moving a line rather than a patch raises
  the minimum for anyone building from source.
- **Building from source needs a Go that will fetch the toolchain `go.mod`
  names.** A distro-packaged Go that defaults `GOTOOLCHAIN=local` refuses the
  build. Setting `GOTOOLCHAIN=auto` is the whole fix, and nothing in the
  repository says so yet.
- **The comment budget has no headroom**: 25% of code against a ceiling of 25%.
- **The gate cannot be reopened without restarting bivy** (ADR-017).
- **The User-Agent decision is open.** ADR-020 is proposed, not accepted.
- PLAN.md §13 still lists the open decisions.
