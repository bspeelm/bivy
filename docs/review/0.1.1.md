# 0.1.1

A release-machinery release. Nothing in the program changed; what changed is
whether its claims about itself hold.

## What changed since 0.1.0

- **`make dist` pins the compiler** to the version `go.mod` names. 0.1.0's
  README offered a rebuild-and-compare in place of a signature, and the offer
  did not hold: two Go releases turn the same source into different binaries,
  so a rebuild on a machine with a different Go produced different bytes. The
  README now also states the second condition — the checkout has to be clean,
  because Go stamps the commit and the tree's dirtiness into the binary.
- **The integration tests run on a schedule**, daily and on request, on Linux
  and macOS, blocking nothing. They need a real mpv and the live network; the
  gate needs neither.
- **ADR-015**: the extractor is not exercised in CI, and no credential is
  added to make it possible.
- **The playback test reports what mpv complained about**, not just that
  something failed.

## What was checked

| check | result |
|---|---|
| `make check` on Linux and macOS, in CI | green |
| `make crossbuild` | all four platforms compile |
| `make dist-reproducible` | two builds, byte-identical checksums |
| the scheduled integration workflow, both platforms | green |
| rebuilding the published 0.1.0 archives | identical, once the toolchain matched |

That last row is the one worth stating plainly, because it is the claim this
release exists to make true. A clean checkout of the v0.1.0 tag, rebuilt with
the compiler `go.mod` names, produced checksums identical to the four archives
published on the release page. Rebuilt with a newer Go, it did not. From 0.1.1
onward `make dist` handles that itself, so the offer holds without the reader
knowing to pin anything.

The integration suite ran on hosted runners for the first time. Everything it
covers passed on both platforms, which means the mpv socket handshake, the
flag set and the process hygiene have now executed on macOS — the first time
any of this has run on a Mac.

## What was not checked

Unchanged from 0.1.0, and one addition at the top.

- **Stream resolution and playback are not covered by CI, and cannot be.**
  Hosted runners are bot-challenged, and the only remedy the error offers is a
  cookie, which ADR-004 refuses. Pressing enter and getting a video — the one
  thing anybody actually does with bivy — is verified by hand and by nothing
  else. It was verified by hand for this release: a real video, resolved by
  mpv's own extractor hook, played to its end and reported `end-file eof`.
- **Nobody has launched bivy on macOS.** The suite runs there, the binary
  cross-compiles, and now the integration tests run there too — but no person
  has started the program on a Mac. PLAN.md §12 asks for that pass and it is
  still outstanding.
- **Thumbnails have no automated test that draws pixels**, because no test can
  assert what a terminal put on a screen. Confirmed by eye on Linux, in a
  terminal speaking the kitty protocol inside a multiplexer. Unrun by any
  human on macOS.
- **Whether a terminal answers the cell-size query through a multiplexer is
  unknown.** When it does not, bivy assumes a size and the picture is softer
  than it needs to be. Nothing fails.
- **No security review by anyone outside this project.**
- **Nothing has been tested at scale** — a handful of followed channels, not
  hundreds.
- **The archives are not signed** (ADR-014). The checksums detect a damaged
  download, not a substituted one. Reproducibility is what carries that
  weight, which is why the fix above was worth a release of its own.

## Known outstanding

Unchanged: playback from inside a container needs the host's mpv, and PLAN.md
§13 still lists the open decisions.
